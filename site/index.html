Rust · WebAssembly · No FFmpeg

Frame-exact video and audio,
native and in the browser.

zvidlib decodes, encodes and muxes HEVC, AV1, VP8 and VP9 video and AAC, Opus and Vorbis audio in MP4 and WebM, from one API on desktop and the web. Ask for frame n and get exactly frame n; ask for a sample range and get exactly those samples. Write frame n and the audio stays in sync.

import init, { MediaInput } from "zvidlib";
await init();

const input = await MediaInput.open(blob);
const video = input.video(0);

// Exactly frame 4812, not the keyframe before it.
const frame = await video.get(4812n);
draw(frame.pixels, frame.width, frame.height);

Indexed get and put

Every read returns the exact frame in presentation order, even in streams full of B-frames and long groups of pictures. Decoded frames and decoder state carry over between calls, so sequential reads stay fast.

Instant scrubbing

A built-in seek-preview tier answers any position in constant time while the exact frame decodes behind it. That's what makes a timeline drag feel immediate.

Sample-exact audio

AAC, Opus and Vorbis decode and encode alongside the video. Read any exact sample range with getRange, or exactly the samples a video frame covers. Priming, padding and edit lists are handled, so gapless round trips come back sample for sample, and audio is muxed in sync with the video into MP4 and WebM.

One API, two targets

The same model works in Rust on Windows, macOS and Linux, and in JavaScript through WebAssembly, with BigInt frame indices, Blob and stream I/O, and stable error codes.

Hardware first, Rust always

NVDEC, Media Foundation (NVENC, Quick Sync, AMF), VideoToolbox and WebCodecs when the host has them, and pure-Rust codecs checked against libvpx and libdav1d when it doesn't.

No FFmpeg

No C toolchain, no system packages, no GPL. Every codec and direction is a Cargo feature, so an app builds only what it uses.

Quick start

One crate for Rust, one package for the browser.

cargo add zvidlib
let source = MemorySource::new(std::fs::read("clip.mp4")?);
let movie = block_on(Mp4Demuxer::open(&source, Mp4DemuxerOptions::default()))?;
let track = movie.tracks.iter().find(|t| t.kind == TrackKind::Video).unwrap();
let samples = block_on(track.to_encoded_video_samples(&source, &limits))?;

let mut reader = ExactFrameReader::new(&native_av1_video_decoder_factory(), config, samples, limits)?;
// Exactly presentation frame 400, never the nearest keyframe.
let frame = reader.get(FrameIndex(400), &CancellationToken::new())?;

Trim the build with Cargo features, for example default-features = false, features = ["vp9-decoder"]. The README has complete read and write programs.

npm install ./zvidlib-web-vX.Y.Z.tgz  # from the latest GitHub release
import init, { CreateOptions, MediaOutput, VideoFrame } from "zvidlib";
await init();

const options = new CreateOptions("webm");
options.videoCodec = "vp9";
options.setTimeline(30, 1, 48_000);
const output = await MediaOutput.create(options);

for (let n = 0n; n < 90n; n++) {
  draw(ctx, n);
  const { data } = ctx.getImageData(0, 0, width, height);
  await output.video(0).put(n, VideoFrame.rgba(width, height, data));
}
const webm = await output.finish(); // Blob { type: "video/webm" }

zvid

A collaborative, canvas-based video editor for the browser and desktop. The editor draws each frame onto a canvas, and zvidlib encodes HEVC or AV1 with AAC audio and writes the MP4, in the browser and in the native app. Its DAW capture plugin, ZVID Capture, records cameras from inside Ableton Live through zvidlib's encoders and muxer.
