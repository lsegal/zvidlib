# Changelog

All notable changes to zvidlib will be documented in this file.

## Unreleased

- Deblock with the AV1 spec's exact wide-filter constants. The in-loop deblocking filter's wide 8-tap and 14-tap luma kernels (§7.14.6.3 `filter8` and §7.14.6.4 `filter14`) previously used a documented symmetric triangular-weighted average as a stand-in for the spec's weighted-sum constants; they now apply the normative per-output weight tables and the spec's `Round2` rounding shift, so wide-filtered luma edges match the reference decoder's output instead of only approximating it. The scalar path and the SSE4.1/AVX2/NEON kernels share one weight table and stay bit-exact with each other on every instruction set the host supports, and wide-filter output is additionally checked against spec-derived vectors rather than only against the crate's own scalar path. The vector kernels' rounding is now an arithmetic shift rather than a division, so `I32x::div_small_nonneg` and its floating-point exactness argument are gone. Chroma still always takes the narrow 4-tap filter; the spec's 6-tap wide chroma filter remains out of scope, as documented in `deblock_frame`.
- Recover the AV1 narrow-filter deblocking throughput that in-kernel boundary handling cost. The vector kernels now finish a whole vector of filtered samples with each instruction set's own saturating pack (`packus_epi32` + `packus_epi16` on SSE4.1/AVX2, `vqmovun_s32` + `vqmovn_u16` on NEON) written as a single machine word, instead of spilling 32-bit lanes to a stack scratch buffer and copying them out a byte at a time; that store serves deblocking, CDEF and Wiener restoration. The narrow vertical-edge deblocking filter additionally reads and writes its window as one unaligned 32-bit word per row rather than one byte per tap per row, separating the four taps with vector shifts, which removes both the gather staging buffer and the scatter that followed it. Frame borders, tile/superblock boundaries, partial rows and columns, and the wide 8- and 14-tap filters keep their existing coverage, and every backend stays bit-exact against the scalar reference. Measured on a 1920x1080 luma frame with NEON on an Apple Silicon host (`--release`, `tests/av1_simd_bench.rs`): full-frame deblocking 3.88 -> 2.84 ms, which is back under the 2.9 ms the interior-only kernels reached before boundary handling moved into the kernel.
- Add a criterion benchmark suite (`cargo bench`) with a shared, once-per-process fixture module over the bundled `examples/media/BigBuckBunny.mp4` HEVC sample and the checked-in AV1 elementary streams, a synthetic YUV420 frame-sequence builder for encoder inputs that does not require decoding first, and frames/sec plus megapixels/sec throughput reporting. Benchmarks are native-only, an explicit `[profile.bench]` keeps them on the shipped `lto = "fat"` / `codegen-units = 1` code generation, and the bundled 1080p sample is gated behind `ZVIDLIB_BENCH_LARGE=1` so the default run stays fast. A new additive, off-by-default `simd` cargo feature tags every criterion group name (`hevc_decode_1080p/simd=off` vs `.../simd=on`) so the two arms record separately; see `benches/README.md`.
- Extend the AV1 SIMD transform coverage from the 4- and 8-point inverse DCT to the whole non-lossless inverse transform set: the 16- and 32-point inverse DCT and the 4-, 8-, and 16-point inverse ADST, in every vertical/horizontal combination including the flipped-ADST output reversals (`ADST_DCT`, `DCT_ADST`, `ADST_ADST`, `FLIPADST_DCT`, `DCT_FLIPADST`, `FLIPADST_FLIPADST`, `ADST_FLIPADST`, and `FLIPADST_ADST`, which `Av1TxType` now names alongside the existing `DCT_DCT` and `IDTX`). `inverse_transform` accepts 16x16 and 32x32 blocks, SSE4.1/AVX2 kernels run on `x86_64` and NEON on `aarch64`, and every backend is asserted bit-exact against the scalar butterflies for each instruction set the host supports. The vector kernels also stopped being product-limited: a round-shifted dot product now splits each operand around bit 14 and accumulates the halves separately, so only the *result* of a butterfly stage has to fit a 32-bit lane. That raises the magnitude at which a coefficient block stays vectorized from 30000 to 2^25 (4-point) through 2^20 (32-point) - about a thousandfold - instead of dropping wide-dynamic-range blocks to scalar. Measured on a 1920x1080 luma frame with NEON on an Apple Silicon host: inverse DCT 2.7x (4x4), 2.2x (8x8), 2.0x (16x16), and 1.8x (32x32), and inverse ADST 2.1x (8x8) and 1.9x (flipped 16x16).
- Vectorize the AV1 transform butterflies and in-loop filter pixel kernels with runtime CPU feature detection: SSE4.1 and AVX2 on `x86_64`, NEON on `aarch64`, and the existing scalar code as the fallback everywhere else (including `wasm32`). The lossless 4x4 Walsh-Hadamard transform, the 4- and 8-point inverse DCT, deblocking's narrow 4-tap filter and its wide 8-tap and 14-tap filters, CDEF's direction search and filter, and both loop-restoration filters (Wiener and self-guided) now run through `zvidlib::av1_simd`, which is bit-exact with the scalar path rather than approximately equal. No filter position falls back to scalar for where it sits in the plane: the kernels reproduce the scalar path's edge replication for taps that leave the plane and write only the positions asked for, so frame borders, tile/superblock boundaries and the partial rows and columns at the right and bottom edges stay vectorized, as do runs that straddle transform blocks of different filter lengths. Coefficient blocks whose magnitudes could overflow a 32-bit lane still take the scalar transform path, and the equality with scalar output is asserted for every instruction set the host supports, with explicit frame-border, partial-row/column and wide-filter coverage. Measured on a 1920x1080 luma frame with NEON on an Apple Silicon host (`--release`): deblocking 5.4x, deblocking with frame-wide 32x32 transform blocks (so every edge takes the 14-tap filter, previously entirely scalar) 3.4x, deblocking of boundary-dominated 33x17 planes 3.9x, CDEF 1.4x, Wiener restoration 1.4x, self-guided restoration 2.7x, and inverse DCT 2.4x faster than the scalar path.
- Add an HEVC encoder-side RDO planner that evaluates coding-block partition candidates and reference-frame motion candidates through `hevc::engine::encoder::rdcost::sad` / `satd`, including scalar-vs-dispatched bitstream identity coverage for the current PCM writer and an ignored end-to-end RDO throughput benchmark.
- Add AV1 smooth (`SMOOTH`, `SMOOTH_V`, `SMOOTH_H`) and directional intra prediction helpers to the shared reconstruction layer, with smooth-weight tables, directional edge filtering/upsampling, runtime-dispatched entry points, and bit-exact reconstruction coverage across AV1 block sizes.
- Vectorize HEVC intra prediction (`hevc::engine::intra_pred`) with runtime-dispatched SIMD for reference-sample smoothing, planar rows, DC fills, and angular interpolation. SSE4.1/AVX2 kernels run on x86_64, NEON kernels run on aarch64, and every other target keeps the scalar fallback. The intra-prediction test matrix now compares each available backend against scalar output for all modes and 4x4/8x8/16x16/32x32 blocks.
- Speed up the pure-Rust HEVC decoder's inter prediction (`hevc::engine::inter_pred`) with SIMD: the §8.5.3.3.3.2 8-tap luma and §8.5.3.3.3.3 4-tap chroma fractional-sample interpolation filters and the §8.5.3.3.4 default and explicit weighted sample-prediction combines now run on SSE4.1/AVX2 kernels on x86_64 and NEON kernels on aarch64, selected once per process by runtime CPU feature detection and falling back to the existing scalar code on every other target (including wasm32). Decoded pixel output is unchanged and bit-exact against the scalar path on every backend; the bundled 1920x1080 sample decoded about 18% faster in `--release` on the profiled aarch64/NEON host (~22.3 -> ~26.4 fps), with the two-dimensional 8-tap luma filter itself about 2.4x faster.
- Vectorize the native HEVC decoder's §8.6.4 inverse transform butterflies (the 4x4/8x8/16x16/32x32 inverse DCT and the 4x4 DST) and §8.6.3 dequantization scaling loop with runtime-dispatched AVX2/SSE4.1 (x86_64) and NEON (aarch64) kernels, falling back to the scalar path on other targets, on hosts without those CPU features, and for extended-precision coefficient ranges. The inverse transform additionally skips zero inputs instead of accumulating them. Decoded output is bit-identical to the previous scalar implementation for every transform size, bit depth, and `qP`.
- Add SIMD-accelerated AV1 inter prediction primitives (`av1_mc`): the separable sub-pixel interpolation filters of spec §7.11.3.4 (the `Subpel_Filters` eight-tap regular/smooth/sharp sets, their narrow four-tap variants for blocks of four samples or fewer, and bilinear) plus compound prediction blending (average, distance-weighted, and the masked blend shared by wedge and difference-weighted compound, including difference-mask generation). SSE4.1 and AVX2 kernels on `x86_64`, NEON on `aarch64`, and a scalar fallback everywhere else (including `wasm32`) are selected by cached runtime CPU feature detection, and every vector backend is bit-exact with the scalar reference across block sizes, filters, sub-pel phases, and compound modes. `Av1InterDecoder` now motion-compensates whole coding blocks through these primitives instead of one sample at a time, with unchanged decoded output. The interpolation benchmark measured 3.2x (NEON, Apple M-series, `--release`) over the scalar kernels.
- Vectorize the HEVC in-loop filters, the two decode stages that touch every reconstructed sample of every picture. A new crate-internal kernel module adds SSE4.1 and AVX2 paths on `x86_64` and NEON on `aarch64`, selected by a cached runtime CPU feature probe with a scalar fallback everywhere else (including `wasm32`), plus contiguous four-sample gather/scatter for deblocking edge segments. SAO band- and edge-offset application runs at the widest available vector, while the §8.7.2 deblocking filter taps map a four-row edge segment onto four `i32` lanes. On a 1920x1080 reconstructed luma frame (Apple M-series, NEON) SAO measured ~2.6x and deblocking ~1.4x faster than the scalar path in `--release`, and ~3.0x / ~1.5x in the crate's `dev` profile. Decoded pixel output is unchanged: the vector kernels are asserted bit-exact against the spec-shaped scalar implementations across boundary strengths, QP values, bit depths, and every SAO type, band position and edge class.
- Install ALSA development headers in the Docs workflow so `cargo doc --features native` can build rustdoc on Ubuntu runners.
- Vectorize the AV1 intra prediction and reconstruction kernels shared by `Av1IntraFrame::reconstruct_block`, the AV1 intra decoder, and the AV1 inter decoder's intra blocks. The DC neighbor sum, the paeth predictor, and the residual-add-and-clamp inner loop now run through the new `av1_intra_pred` kernels, which dispatch to AVX2 or SSE4.1 on x86/x86_64 and NEON on aarch64 at run time and fall back to the portable scalar path everywhere else (including the `wasm32` web decode path). Output is bit-exact with the previous scalar code; block reconstruction measured 1.1x-9.6x faster across 8x8 to 64x64 blocks (paeth prediction alone 5x-50x) on an aarch64 host.
- Add SIMD-accelerated SAD and Hadamard SATD distortion metrics for HEVC encoder-side rate-distortion cost estimation (`hevc::engine::encoder::rdcost`), with SSE4.1 and AVX2 paths on x86_64, NEON on aarch64, and a portable scalar fallback selected by cached runtime CPU feature detection (including wasm32). Every vectorized path is bit-identical to the scalar reference across all HEVC candidate block shapes and stride combinations, so mode decisions and bitstream output are unchanged; a built-in throughput benchmark measured 2.8-3.7x (SAD) and 4.5-6.6x (SATD) over the scalar path on an aarch64/NEON host.
- Fix browser video playback (`VideoStream.get()` through the `WebCodecs` backend, as exercised by the `web_canvas` example) holding the bundled 1920x1080 sample under 1 fps in Chrome even with hardware HEVC decoding. The decode session used to reset and re-decode from the GOP's key frame on almost every call for content with reordered decoder output (HEVC hierarchical B-frames), and converted every frame the decoder emitted to RGBA rather than just the requested one. It now reuses the open session unless the requested frame has already been emitted since the last reset (matching the native `ExactFrameReader` policy), keeps decoded frames as live `VideoFrame` handles and converts only the frame a caller asks for, flow-controls submission against the decoder's queue depth, and closes every `VideoFrame` deterministically on eviction, reset, and session drop so Chrome no longer warns that a `VideoFrame` was garbage collected without being closed. The bundled 32-second 1080p clip measured 23.99 fps against its 24 fps source rate on a hardware-HEVC macOS host, up from 0.2-1.0 fps.
